# Program with asyncio keywords but running synchronously

import asyncio

async def make_tea():
    print("Boiling water...")
    await asyncio.sleep(3)
    print("Tea ready")

async def make_toast():
    print("Toasting bread...")
    await asyncio.sleep(2)
    print("Toast ready")

async def main():
    await make_tea()
    await make_toast()

asyncio.run(main())






# What happens why this output?
'''
O/P:
main() finished
Boiling water...
Toasting bread...
'''
1. create_task creates a task object and puts it to event loop (Not paused, not started object - which means
   once the event loop is ready to pick up any other, it can take up these).
2. the make_tea and make_toast are in this state.
2. main coroutine is what is running currently and its been waiting oon time.sleep() which is a synchronous sleep.
4. once done, we get "main() finished".
5. Now main coroutine is completed and the event loop is free, so it runs these tasks.
6. In the mean time asyncio.run runs some cleanup by creating a task in event loop. When make_tea and make_toast
   waiting on async timer, this cleanup runs and wipes out all pending tasks and the event loop itself. 
   As nothing exists to be ran, program ends.

import asyncio
import time

async def make_tea():
    print("Boiling water...")
    await asyncio.sleep(3)
    print("Tea ready")

async def make_toast():
    print("Toasting bread...")
    await asyncio.sleep(2)
    print("Toast ready")

async def main():
    task1 = asyncio.create_task(make_tea())# <- no await here
    task2 = asyncio.create_task(make_toast())
    time.sleep(20)
    print("main() finished")

asyncio.run(main())

Correction: await doesn't hand off to a new coroutine directly

await <coroutine_obj> doesn't pull the coroutine object out and run it as a separate, 
competing thing on the ready queue. Instead, the awaited coroutine is run inline, 
as a direct continuation of the current one — think of it like a regular function call: the current coroutine's 
execution steps into the awaited coroutine and runs its code right there, on the same turn. 
There's no scheduling decision made and no ready-queue entry created for it. 
If the awaited coroutine never hits its own await on something else, it runs start-to-finish immediately, 
and control returns to the line right after the await — no other coroutine gets a turn in between.

The only time an actual pause and a return to the event loop happens is when that awaited coroutine reaches an await on 
something not-yet-ready — a timer, a socket, or a Task. That's the real pause point, 
not the initial await itself. This is different from await task1 on a create_task-created Task, 
which you traced earlier — a Task is scheduled and picked up by the event loop separately, 
but awaiting a plain coroutine object directly (await make_tea()) just runs it in-place, like a function call.
